# skill-creator 用プロンプトの組み立て方

read_sheet.py の出力 JSON（status が "ok" のもの）から、下の構成でプロンプトを作る。
見出しと順序は固定する。skill-creator の「Capture Intent」「Interview and Research」で
聞かれる内容に先回りして答える構成になっているため、順序を崩すと聞き直しが増える。

## 組み立てのルール

- **シートに書かれていないことを足さない。** 補足が必要に見えても推測で埋めず、
  「未記入」「記入者に確認が必要」と書く。skill-creator 側がユーザーに質問できるようにするため。
- 記入者の言葉はできるだけそのまま引用する。言い換えると意図がずれることがある。
- 推奨・任意の項目が空欄なら、該当箇所に「（未記入）」と書く。項目ごと消さない。
  空欄であること自体が skill-creator にとって「ここは質問すべき」という情報になる。
- 選択肢で答えた項目（A-07 など）はそのままの値を書く。
- 表の項目は Markdown の表か番号付きリストにする。行の順序を保つ（特に D-02 の手順）。
- 添付ファイルは、作業ディレクトリ内の実際のパスで書く。
- 生成する SKILL は日本語で書くよう明記する（name だけは半角英小文字とハイフン）。

## プロンプトの構成（この見出しで出力する）

```markdown
# 新しいSKILLの作成依頼

以下は、非エンジニアを含む記入者がヒアリングシート（skill-seed テンプレート v{template_version}）に
記入した要件です。この内容をもとに SKILL を作成してください。

## 作成時の前提
- SKILL.md の本文と description は**日本語**で書くこと（name は半角英小文字・ハイフン）
- シートに書かれていない仕様は推測せず、私（ユーザー）に質問すること
- 「（未記入）」の項目は、必要なら私に質問すること
- 利用環境: {A-07}（Claude.ai なら /mnt/user-data/ 配下での入出力、Claude Code ならローカルパスでの入出力を想定）
- 利用者のITへの慣れ: {A-06}（「苦手な人もいる」なら、SKILL が利用者に返す文章は専門用語を避ける）

## 1. 何をするSKILLか
- 呼び名: {A-01}
- name の候補: {A-02 または「未記入（提案してください）」}
- できるようにしたいこと: {A-03}
- 背景・困りごと: {A-04}
- 利用者: {A-05}／頻度: {A-08}

## 2. いつ使うか（description に反映すること）
### 使ってほしい依頼文の例
{B-01 を番号付きリストで}
### キーワード
{B-02}
### 使ってほしくない場面
{B-03 を「場面 — 理由」のリストで}
### 関連・重複しそうな既存SKILL
{B-04}

## 3. 入力
{C-01 を表で: 入力の名前 / 種類 / 形式 / 毎回あるか / 中身の説明 / サンプル}

## 4. 作業手順
- 順序の厳密さ: {D-01}
{D-02 を表で: No / やること / 判断のポイント / 使う道具・情報 / 人の確認}
「人の確認が必要＝はい」の手順では、SKILL の中でユーザーに確認してから次に進むよう指示すること。

## 5. 出力
- 形式: {E-01}
- 構成:
{E-02 をそのまま。空欄なら下の1行を書く}
（未記入。理想の出力例 {E-06 のパス} から見出しや項目の並びを読み取って構成とすること）
- 文体: {E-03}／分量: {E-04}／ファイル名: {E-05}
- 理想の出力例: {E-06 のパス}
- 合格基準: {E-07}

## 6. ルール
{F-01 を「種類」でグループ化したリスト。理由も併記}
{A-07 が「Claude Code」で、F-01 に「絶対にやらない」の行がある場合のみ、下の1文を書く}
「絶対にやらない」のうち、ファイルの削除や外部への送信などの操作は、hooks で機械的に防げるか検討し、防げるものは hooks での制限を私に提案すること（文章の書き方に関するルールは対象外）。
### 社内用語
{F-02}

## 7. 迷ったとき・例外
- 基本方針: {G-01}
{G-02 を「こんなとき → こうする」のリストで}

## 8. テスト
- テストの希望: {H-01}
{H-02 を表で。添付ファイルはパスで}
「はい」の場合は、上記をそのまま skill-creator のテストケース（evals/）にすること。
「おまかせ」の場合は、テストの要否を skill-creator の判断で提案すること。

## 9. 参考資料・外部サービス・機密情報
{I-01 を表で: 資料名 / パス・保存場所 / 使い方}
「SKILLに同梱する」資料は、SKILL の references/ または assets/ に入れること。
- 外部サービス: {I-02}
- 機密情報: {I-03}／扱い方: {I-04}

## 添付ファイル一覧
{作業ディレクトリに置いたファイルのパスと、シートのどこで参照されているか}
```
